================================================================================
PRISM PIPELINE ANALYSIS - QUICK REFERENCE
================================================================================

QUESTION: Does the official evaluation script's pipeline implementation match training?

ANSWER: NO - Critical channel dimension mismatch found.

================================================================================
THE ROOT CAUSE (ONE LINE)
================================================================================

Line 382 of prism_backend.py uses transformer.config.in_channels instead of 
the actual VAE output dimension (vae.config.z_dim), causing dimension mismatch.

================================================================================
HOW IT AFFECTS THE 4270 NPZ FILES
================================================================================

Eval Script Flow:
  script/eval/eval_prism_t2m_hml3d.py 
    ↓ calls
  pipeline(prompts=caption, num_frames=num_frames, ...)
    ↓ delegates to
  PrismPipeline.__call__()
    ↓ which calls
  PrismARPipeline.__call__()
    ↓ which calls
  generate_single_segment()
    ↓ at line 382, creates latents with WRONG channel count
    ↓ transformer receives mismatched shape
    ↓ ALL 4270 NPZ outputs corrupted identically

================================================================================
TRAINING vs INFERENCE COMPARISON
================================================================================

                        TRAINING                INFERENCE
Location                prism_trainer.py        prism_backend.py (line 382)
Channel source          encode_motion() output  transformer.config.in_channels
Channel value           VAE's actual z_dim      Potentially WRONG value
Latent shape            [B, C_actual, T, J]     [B, C_config, T, J]
Transformer input       Correctly matched       MISMATCHED ❌

================================================================================
WHY ALL 4270 ARE DEFORMED IDENTICALLY
================================================================================

1. All use same checkpoint (same wrong config, same VAE)
2. All use same parameters (50 steps, guidance 5.0)
3. All hit the same channel mismatch at line 382
4. Transformer receives wrong number of channels consistently
5. Decoder produces corrupted output consistently
6. Result: Identical deformation pattern in ALL 4270 files

This PROVES it's not a random bug - it's systematic channel mismatch.

================================================================================
VERIFICATION STEPS
================================================================================

1. Check config values:
   grep -r "in_channels" configs/prism/*.py
   grep -r "z_dim" configs/prism/*.py

2. Print during inference (add to prism_backend.py line 382):
   print(f"transformer.config.in_channels = {self.transformer.config.in_channels}")
   print(f"vae.config.z_dim = {self.vae.config.z_dim}")

3. They should be equal. If not, that's the problem.

================================================================================
THE FIX
================================================================================

Replace line 382 in hftrainer/pipelines/motion/prism_backend.py:

BEFORE:
    num_channels_latents = self.transformer.config.in_channels

AFTER:
    # Use actual VAE output dimension instead of config value
    num_channels_latents = self.vae.config.z_dim
    
    # Or add safety check:
    if self.transformer.config.in_channels != self.vae.config.z_dim:
        raise ValueError("Channel mismatch between transformer config and VAE!")

================================================================================
KEY INSIGHT
================================================================================

The latent channel dimension is the INTERFACE between:
  1. VAE (outputs latents with shape [B, C_vae, T, J])
  2. Transformer (expects input shape [B, C_transformer, T, J])

For correct inference, C_vae MUST EQUAL C_transformer.

Training works because it gets C from actual VAE output.
Inference fails because it uses config value that doesn't match.

================================================================================
PROOF POINTS
================================================================================

1. All 4270 NPZ files deformed identically
   → Not random error (would have variation)
   → Systematic error (same cause, same effect)

2. Training uses encode_motion() directly
   → Gets correct channel dimension
   → Works fine

3. Inference uses transformer.config.in_channels
   → Gets potentially wrong channel dimension
   → Fails systematically

4. Line 382 is where inference creates random latents
   → Only place inference differs from training on latent creation
   → Only place where channel mismatch can occur
