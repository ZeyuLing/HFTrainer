3. PIPELINE (INFERENCE)
================================================================================

CLASS: HyMotionT2MPipeline
FILE:  hftrainer/pipelines/motion/hymotion_t2m_pipeline.py (172 lines)

Key methods:
  __init__(bundle, num_steps=50, text_guidance_scale=5.0)
  __call__(batch) → Dict with 'latent', 'rot6d', 'transl', 'keypoints3d'

Flow:
  1. Text encoding (Qwen3 + CLIP-L)
  2. Classifier-free guidance preparation (if scale > 1.0)
  3. ODE integration via torchdiffeq.odeint
     - Initial noise: y0 ~ N(0, I)
     - Time steps: t ∈ [0, 1] with num_steps+1 points
     - Solver: Euler method (default)
  4. Denormalization: motion = x_clean * std + mean
  5. Optional: FK to 3D joint positions

USAGE:
  pipeline = HyMotionT2MPipeline(bundle, num_steps=50, text_guidance_scale=5.0)
  output = pipeline({
      'tgt_length': [360],
      'caption': ['a person walks forward slowly'],
  })

OUTPUT FORMAT:
  {
    'latent': (B, T, D),        # (1, 360, 201) denormalized motion
    'rot6d': (B, T, J, 6),      # 6D rotations per joint
    'transl': (B, T, 3),        # Root translation
    'keypoints3d': (B, T, J, 3) # 3D FK positions (optional)
  }

7. NPZ OUTPUT FORMAT
================================================================================

Generated motions are saved as compressed NumPy archives:

np.savez_compressed(path,
    motion_135=(T, 135),        # Main output: 6D rotation + translation
                                # - Translation (3): XYZ
                                # - Rotation 6D (132): 22 joints × 6
    positions=(T, 22, 3),       # 3D joint keypoints via forward kinematics
    translation=(T, 3),         # Root translation channel
)

Dimensions:
- T: number of frames (typically 360 @ 30fps = 12 seconds)
- 135: [3 (translation) + 132 (6D rotation for 22 joints)]
- 22: SMPL joint count
- 3: XYZ coordinates

Loading:
  data = np.load('motion.npz')
  motion_135 = data['motion_135']         # (360, 135)
  positions_3d = data['positions']        # (360, 22, 3)
  translation = data['translation']       # (360, 3)

8. KEY PARAMETERS
================================================================================

Inference:
  num_steps: 50              ODE solver integration steps
                             (↑ quality, ↓ speed)
  text_guidance_scale: 5.0   Classifier-free guidance strength
                             (1.0 = no guidance, ignore text)
  tgt_length: 360            Motion duration in frames
  batch_size: 1              Parallel samples (VRAM limited)

Quality:
  cfg_scale=1.0: Random, ignores text
  cfg_scale=3.0: Balanced text-motion trade-off
  cfg_scale=5.0: Strong text alignment (DEFAULT)
  cfg_scale=7.0: Very strict text following
  cfg_scale>10:  Over-constrained (not recommended)

Performance:
  num_steps=20:  ~0.5s per motion (fast, lower quality)
  num_steps=50:  ~1-2s per motion (DEFAULT)
  num_steps=100: ~3-4s per motion (high quality)
  Memory:
    batch_size=1: ~0.5 GB
    batch_size=8: ~2.5 GB

11. TROUBLESHOOTING
================================================================================

Q: "No checkpoint found"
A: Verify: checkpoints/HY-Motion-1.0/HY-Motion-1.0-Lite/latest.ckpt (1.8 GB)

Q: "input_dim/output_dim mismatch"
A: Use config: configs/hymotion_t2m/hymotion_t2m_201dim_046b.py (NOT M2M)
   Ensure: input_dim=output_dim=201

Q: "VACE applied (should be motion_dim only)"
A: HyMotion T2M does NOT use VACE conditioning
   T2M: input_dim = motion_dim (✓)
   M2M: input_dim = motion_dim * 4 (❌ for T2M)

Q: "Text encoding fails"
A: Check bundle._text_encoder_cfg is set:
   {'llm_type': 'qwen3_embedding', 'sentence_emb_type': 'clipl', ...}

Q: "Out of memory (OOM)"
A: - Reduce batch_size or tgt_length
   - Use num_steps=20 for faster inference
   - Split inference across multiple GPUs
