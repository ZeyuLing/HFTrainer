## Executive Summary

**SOAR (Self-Correction for Optimal Alignment and Refinement)** is a reward-free post-training method that addresses **exposure bias** in rectified-flow diffusion models. The key innovation is correcting the model on **off-trajectory states** generated by the model itself during inference, using self-supervised correction targets derived from the clean training data.

### Why SOAR for HyMotion M2M?

| Problem | Impact on M2M | Solution |
|---------|---------------|----------|
| **Exposure bias** | Train uses GT on-trajectory states; inference uses model's own accumulated errors | SOAR provides dense per-step correction on off-trajectory states |
| **Boundary discontinuity** | Hard transition at known↔generated region boundary | Mask-aware SOAR keeps known regions clean while fixing generated regions |
| **Temporal propagation** | Early errors accumulate through 50-step ODE | Re-noising + correction targets fix error accumulation |

**Key metrics improvement (on SD3.5-Medium)**:
- GenEval: +11% (0.70 → 0.78)
- OCR Accuracy: +5% (0.64 → 0.67)
- Human preference: +0.15 PickScore

## Part 2: SOAR Training Step Logic

### High-Level Flow

```
train_step(batch)
├─ 1. _prepare_and_forward(batch)
│     └─ Returns context dict with base forward pass
├─ 2. _compute_base_loss(ctx)
│     └─ Standard on-trajectory velocity MSE loss
├─ 3. _soar_correction_loss(ctx)
│     ├─ STEP R1: Stop-gradient ODE rollout
│     ├─ STEP R2: N auxiliary re-noise + correction forward passes
│     └─ Returns scalar correction loss (averaged over aux points)
└─ 4. Combine: L_total = L_base + soar_lambda * L_corr
```

### Complete Train Step (lines 254-275)

```python
def train_step(self, batch: Dict[str, Any]) -> Dict[str, Any]:
    # Verify velocity parameterisation (only mode supported)
    if self.bundle.pred_type != 'velocity':
        raise NotImplementedError(...)
    
    # 1. Base on-trajectory forward + loss (SFT objective)
    ctx = self._prepare_and_forward(batch)
    base_losses = self._compute_base_loss(ctx)
    base_loss = sum(base_losses.values())
    
    # 2. SOAR correction loss
    corr_loss = self._soar_correction_loss(ctx)
    
    # 3. Combined loss
    total_loss = base_loss + self.soar_lambda * corr_loss
    
    # 4. Return with breakdown
    result: Dict[str, Any] = {'loss': total_loss}
    for k, v in base_losses.items():
        result[f'loss_{k}'] = v.detach()
    result['loss_soar_corr'] = corr_loss.detach()
    return result
```

## Part 3: SOAR Correction Loss Computation

### Method Signature (lines 143-251)

```python
def _soar_correction_loss(
    self,
    ctx: Dict[str, Any],
) -> Tensor:
    """Compute the SOAR correction loss from a base-forward context.
    
    Input context keys:
        x0, x1, x_t, t, pred (v_pred), vace_context, vtxt_input, 
        ctxt_input, tgt_padding_mask, ctxt_mask_temporal, src_mask, 
        generation_mask
    
    Returns: scalar Tensor (averaged over auxiliary points)
    """
```

### STEP R1: Stop-Gradient ODE Rollout (lines 164-186)

**Purpose**: Generate an off-trajectory state by taking one Euler step towards clean.

```python
# Compute t1 = t0 + 1/K (one step closer to t=1, towards clean)
K = float(self.soar_K)
t1 = (t0 + 1.0 / K).clamp(max=1.0)     # (B, 1, 1)
dt = t1 - t0                            # (B, 1, 1), in [0, 1/K]

with torch.no_grad():
    v_rollout = v_pred.detach()         # Stop-gradient velocity
    x_hat = x_t0.detach() + v_rollout * dt  # Off-trajectory state
    
    # Mask-aware: keep known regions clean
    if self.mask_aware_noise and src_mask is not None:
        keep_mask = 1 - src_mask
        x_hat = x_hat * src_mask + x1 * keep_mask
```

**Mathematical basis (Flow Matching convention)**:
- Forward process: `x_t = (1-t)*x0 + t*x1` where x0=noise, x1=clean
- Velocity field: `v = x1 - x0`
- ODE integration: `x(t + dt) ≈ x(t) + v*dt`
- Goal: move from t0 (current noisy timestep) towards t1 (less noisy)

### STEP R2: N Auxiliary Re-Noise + Correction (lines 187-251)

**Loop**: For each of N auxiliary points:

#### Sub-step R2a: Sample Auxiliary Timestep (lines 196-210)

```python
for _ in range(self.soar_num_aux):
    # Sample t' uniformly in [0, t1] (towards noise direction from x_hat)
    rand = torch.rand(B, 1, 1, device=device, dtype=x1.dtype)
    t_prime = t1 * (1.0 - rand)         # (B, 1, 1), in [0, t1]
    alpha = 1.0 - rand                   # fraction of x_hat vs x0
    
    # Re-noised state: mix x_hat (at t1) with x0 (pure noise)
    # When rand=0 (t'=t1): z_re = x_hat
    # When rand=1 (t'=0):  z_re = x0
    with torch.no_grad():
        z_re = alpha * x_hat + (1.0 - alpha) * x0
        
        # Mask-aware: keep known regions clean at new timestep
        if self.mask_aware_noise and src_mask is not None:
            keep_mask = 1 - src_mask
            z_re = z_re * src_mask + x1 * keep_mask
```

#### Sub-step R2b: Compute Correction Target (lines 216-226)

```python
# Correction target velocity (with guard against numerical blow-up)
one_minus_tp = (1.0 - t_prime).clamp_min(sigma_clamp)
with torch.no_grad():
    v_corr = (x1 - z_re) / one_minus_tp
```

**Mathematical derivation**:
- At off-trajectory point z_re at timestep t', the model should predict velocity
  that steers towards clean target x1
- FM convention: velocity that takes z_re to x1 over remaining (1-t') time is:
  `v = (x1 - z_re) / (1 - t')`
- The denominator clamp prevents division by very small numbers (analogous to 
  `t_eps=0.05` in the x1-parameterisation base trainer)

#### Sub-step R2c: Forward on Off-Trajectory Point (lines 227-237)

```python
# Forward pass WITH gradient tracking (only this carries gradients)
z_re_input = torch.cat([z_re, vace_context], dim=-1)
t_prime_scalar = t_prime.view(-1)     # (B,)
v_off = self.bundle.predict_flow(
    x_input=z_re_input,
    ctxt_input=ctxt_input,
    vtxt_input=vtxt_input,
    timesteps=t_prime_scalar,
    x_mask_temporal=tgt_padding_mask,
    ctxt_mask_temporal=ctxt_mask_temporal,
)
```

#### Sub-step R2d: Compute and Accumulate Correction Loss (lines 239-247)

```python
# Correction loss on generation regions only
corr = self._masked_velocity_loss(
    pred_vel=v_off,                    # model's prediction
    gt_vel=v_corr.detach(),            # correction target (detached)
    generation_mask=generation_mask,   # src_mask (1=generate, 0=known)
    data_mask_temporal=tgt_padding_mask,
)
total_corr = total_corr + corr
valid_count += 1
```

#### Return Averaged Correction Loss (lines 249-251)

```python
if valid_count == 0:
    return x1.new_zeros(())
return total_corr / float(valid_count)  # Average over N auxiliary points
```

## Part 4: Mask-Aware Loss Computation

### Method: _masked_velocity_loss (lines 112-140)

```python
def _masked_velocity_loss(
    self,
    pred_vel: Tensor,           # (B, L, D) model prediction
    gt_vel: Tensor,             # (B, L, D) ground truth / correction target
    generation_mask: Optional[Tensor],  # (B, L, D) 1=generate, 0=known
    data_mask_temporal: Tensor, # (B, L) temporal padding mask
) -> Tensor:
    """Compute SmoothL1 velocity loss weighted by masks.
    
    Mirrors m2m_loss.M2MLoss's velocity-loss masking convention:
      - If generation_mask provided (mask_aware_noise), combine with
        temporal padding mask and average over valid elements
      - Otherwise fall back to per-frame mean over valid temporal frames
    
    Translation-dim upweighting is OMITTED from SOAR correction loss
    to keep it a plain distributional correction signal.
    """
    per_dim = self._smooth_l1_loss(pred_vel, gt_vel)  # (B, L, D)
    data_mask = data_mask_temporal.to(per_dim.device).unsqueeze(-1)  # (B, L, 1)
    
    if generation_mask is not None:
        gen_mask = generation_mask.to(per_dim.device)
        combined = gen_mask * data_mask  # (B, L, D)
        denom = torch.clamp(combined.sum(), min=1.0)
        return (per_dim * combined).sum() / denom
    else:
        per_frame = per_dim.mean(dim=-1)  # (B, L)
        denom = torch.clamp(data_mask.squeeze(-1).sum(), min=1.0)
        return (per_frame * data_mask.squeeze(-1)).sum() / denom
```

**Key design decisions**:
1. **SmoothL1 loss**: Matches parent trainer's base loss function
2. **Generation mask weighting**: Only generated regions contribute to loss
3. **Temporal padding masking**: Sequences of varying lengths handled correctly
4. **No translation upweighting**: SOAR correction is purely distributional, not 
   preserving special treatment of translation dimensions

## Part 8: Gradient Flow and Backpropagation

### Gradient Flow Diagram

```
                    ┌─────────────────────────────────┐
                    │  x_t0  (on-trajectory)          │
                    │  (requires_grad=True)            │
                    └──────────┬──────────────────────┘
                               │
                    ┌──────────▼──────────────────────┐
                    │  model(x_t0, cond, t0)          │ ← GRADIENTS FLOW
                    │  → v_pred (requires_grad=True)   │
                    └──────────┬──────────────────────┘
                               │
              ┌────────────────┼────────────────────────┐
              │                │                        │
    ┌─────────▼────────┐  ┌────▼──────────────┐  ┌─────▼──────────────┐
    │ L_base          │  │ STOP GRADIENT     │  │                    │
    │ = smooth_l1(...) │  │ v_cfg =           │  │                    │
    │ (→ backward)    │  │ v_pred.detach()   │  │                    │
    └─────────────────┘  │ (NO GRADIENTS)    │  │                    │
                         └────┬───────────────┘  │                    │
                              │                  │                    │
                  ┌───────────▼──────────────────┘                    │
                  │  x_hat = x_t0 + v_cfg * dt                        │
                  │  (detached, NO GRADIENTS)                         │
                  └────┬─────────────────────────────────────────────┘
                       │
                  ┌────▼──────────────────────┐
                  │  z_re = α*x_hat + (1-α)*x0│
                  │  (detached, NO GRADIENTS) │
                  └────┬──────────────────────┘
                       │
                  ┌────▼──────────────────────────────────┐
                  │  model(z_re, cond, t')                │ ← GRADIENTS FLOW
                  │  → v_off (requires_grad=True)         │
                  └────┬──────────────────────────────────┘
                       │
                  ┌────▼──────────────────────────────────┐
                  │  L_corr                                │
                  │  = smooth_l1(v_off, v_corr.detach()) │
                  │  (→ backward)                         │
                  └───────────────────────────────────────┘
```

### Key Gradient Boundaries

1. **Base loss forward pass**: Gradients flow through `v_pred`
2. **Rollout step**: `v_pred.detach()` — stop gradients for rollout velocity
3. **Intermediate states**: `x_hat` and `z_re` detached — no gradient flow
4. **Correction forward pass**: Gradients flow through `v_off`
5. **Correction target**: `v_corr.detach()` — target is fixed, not optimized

**Why detach intermediate states?**
- Prevents backprop through the rollout path (would create circular gradient flow)
- Keeps correction loss independent of base loss optimization
- Matches SOAR paper's "stop-gradient rollout" design principle

## Part 14: Troubleshooting

### Issue: `NotImplementedError: SOAR with text CFG`

**Cause**: `soar_cfg_scale != 1.0` with conditional model

**Solution**: Set `soar_cfg_scale=1.0` in config or use unconditional model

### Issue: NaN in loss_soar_corr

**Cause**: Numerical instability in correction target division

**Solution**: Increase `soar_sigma_clamp` (try 0.1 or 0.2)

### Issue: OOM error during training

**Cause**: ~2x memory overhead from dual forward passes

**Solutions**:
- Reduce batch size (currently 14, try 10-12)
- Enable gradient checkpointing
- Reduce `soar_num_aux` (currently 1, already minimal)
- Use smaller `max_grad_norm`

### Issue: loss_velocity increases during SOAR training

**Cause**: Correction loss weight too high

**Solution**: Reduce `soar_lambda` (try 0.05 instead of 0.1)

### Issue: Correction loss not decreasing

**Cause**: Model not learning to correct off-trajectory states (possible with poor base model)

**Solution**: 
- Verify base checkpoint is well-trained (epoch 485, loss ~0.3-0.5)
- Check that mask_aware_noise=True
- Run unit tests to verify computation correctness

## Summary

**HyMotionM2MSoarTrainer** is a minimal, focused extension of the base M2M SFT trainer that adds SOAR correction loss. Key architectural decisions:

1. **Inheritance-based design**: Reuses all data preparation, text encoding, VACE logic from parent
2. **Dual forward passes**: Base forward (on-trajectory) + Correction forward (off-trajectory)
3. **Stop-gradient rollout**: Prevents circular gradients
4. **Mask-aware throughout**: Known regions always clean
5. **Self-supervised correction targets**: No reward model needed
6. **Conservative hyperparameters**: λ=0.1, N=1, K=50 as recommended defaults

**Expected impact**: 5-10% improvement in boundary smoothness and temporal coherence after 5K-10K post-training steps on 8xA100 GPUs.
