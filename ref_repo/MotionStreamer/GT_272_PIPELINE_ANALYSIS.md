# GT 272-Dim Motion Data Pipeline Analysis

## Executive Summary

The **GT 272-dimensional motion representation** in MotionStreamer is generated by a two-stage pipeline:

1. **Data Preparation**: `representation_272.py` (located at `272-dim-Motion-Representation/representation_272.py`)
2. **Format Conversion**: `convert_prism_to_272.py` (for converting PRISM predictions to GT 272-dim format)

Both scripts use **SMPL body model** (NOT SMPLX) and employ **`matrix_to_rotation_6d`** which extracts the **first 2 ROWS** of the rotation matrix (ROW-MAJOR convention).

---

## Key Finding: Rotation Extraction Method

### The Critical Code (Line 116 in representation_272.py):
```python
final_x[:,8+6*njoint:8+12*njoint] = np.reshape(rotations_matrix[..., :, :2, :], (nfrm,-1))
```

**What this does:**
- `rotations_matrix` shape: `(T, 22, 3, 3)` — rotation matrices for T frames, 22 joints
- `rotations_matrix[..., :2, :]` → takes **first 2 ROWS** → shape `(T, 22, 2, 3)`
- Flattens to `(T, 22×6)` = `(T, 132)` which is dims 176-308 of the 272-dim vector

### The Explicit matrix_to_rotation_6d Implementation (face_z_align_util.py, line 961-974):

```python
def matrix_to_rotation_6d(matrix: torch.Tensor) -> torch.Tensor:
    '''
    Converts rotation matrices to 6D rotation representation by Zhou et al. [1]
    by dropping the last row. Note that 6D representation is not unique.
    Args:
        matrix: batch of rotation matrices of size (*, 3, 3)
    Returns:
        6D rotation representation, of size (*, 6)
    [1] Zhou, Y., Barnes, C., Lu, J., Yang, J., & Li, H.
    On the Continuity of Rotation Representations in Neural Networks.
    IEEE Conference on Computer Vision and Pattern Recognition, 2019.
    Retrieved from http://arxiv.org/abs/1812.07035
    '''
    return matrix[..., :2, :].clone().reshape(*matrix.size()[:-2], 6)
```

**This is ROW-MAJOR**: takes first 2 rows, flattens as:
```
6D = [R[0,0], R[0,1], R[0,2], R[1,0], R[1,1], R[1,2]]
     (row 0)            (row 1)
```

## Key Finding: Rotation Source (SMPL, NOT IK)

### The Data Flow:

1. **Input to representation_272.py**:
   - `smpl_85_face_z_transform_joints`: Joint 3D positions (output of FK using SMPL)
   - `smpl_85_face_z_transform`: **SMPL axis-angle parameters** (first 66 dims = 22 joints × 3)
   
2. **Rotation extraction (line 65-67)**:
   ```python
   rotation_smpl_axis_angle = np.load(file.replace('smpl_85_face_z_transform_joints', 
                                                     'smpl_85_face_z_transform'))
   rotations_wxyz = expmap_to_quaternion(rotation_smpl_axis_angle[:, :66].reshape(nfrm, njoint, 3))
   rotations_matrix = quaternion_to_matrix_np(rotations_wxyz)  # nframe, njoint, 3, 3
   ```

3. **The pipeline uses SMPL body model rotations DIRECTLY**, not IK-derived rotations.

## 272-Dim Format Breakdown

Based on representation_272.py and convert_prism_to_272.py:

| Dims | Content | Size | Derivation |
|------|---------|------|-----------|
| 0-1 | Root XZ velocity (heading removed) | 2 | `velocities_root_xy_no_heading` |
| 2-7 | Heading angular velocity (6D rot) | 6 | `matrix_to_rotation_6d(global_heading_diff_rot)` |
| 8-65 | Joint positions (22 joints × 3) | 66 | `positions_no_heading` (XZ-centered, heading-removed) |
| 66-131 | Joint velocities (22 joints × 3) | 66 | `velocities_no_heading` |
| 132-263 | **Joint rotations (22 joints × 6)** | 132 | **`rotations_matrix[..., :2, :]` (ROW-MAJOR, first 2 rows)** |
| **Total** | | **272** | |

### Detailed breakdown from representation_272.py:

```python
# Line 102: size calculation
size_frame = 8+njoint*3+njoint*3+njoint*6  # = 8 + 66 + 66 + 132 = 272

# Lines 105-116: Packing data
final_x[0, 2] = 1          # First frame: identity heading (dim 2 = 1, others 0)
final_x[0, 6] = 1          # First frame: identity heading (dim 6 = 1, others 0)

# Line 109: Heading angular velocity as 6D
final_x[1:,2:8] = matrix_to_rotation_6d(torch.from_numpy(global_heading_diff_rot))

# Line 113: Root velocity XZ
final_x[1:,:2] = velocities_root_xy_no_heading

# Line 114: Local positions (heading removed)
final_x[:,8:8+3*njoint] = np.reshape(positions_no_heading, (nfrm,-1))

# Line 115: Local velocities (heading removed)
final_x[1:,8+3*njoint:8+6*njoint] = np.reshape(velocities_no_heading, (nfrm-1,-1))

# Line 116: Local rotations as 6D (ROW-MAJOR, first 2 rows)
final_x[:,8+6*njoint:8+12*njoint] = np.reshape(rotations_matrix[..., :, :2, :], (nfrm,-1))
```

## Coordinate System & Transformations

### Face-Z Transform (Applied First)
From `face_z_align_util.py::face_z_transform()`:
- Rotates first frame so character faces **Z+ direction**
- Applied to both global root orientation and translations
- This is why GT data is "all initially face Z+" (comment in representation_272.py, line 6)

### Heading Removal
From representation_272.py lines 83-99:
```python
# Calculate heading from root rotation matrix
global_heading = - np.arctan2(rotations_matrix[:,root_idx,0,2], 
                              rotations_matrix[:, root_idx, 2,2])

# Calculate heading rotation as Yaw matrix
global_heading_rot = np.array([rot_yaw(x) for x in global_heading])

# Remove heading from all positions
positions_no_heading = np.matmul(np.repeat(global_heading_rot[:, None,:, :], njoint, axis=1), 
                                 position_data[...,None]).squeeze(-1)

# Remove heading from root rotation only
rotations_matrix[:,0,...] = np.matmul(global_heading_rot, rotations_matrix[:,0,...])
```

This is a **local coordinate frame** approach where:
- XZ plane is locked (character always faces Z+ after heading removal)
- Y (vertical) is global
- Character moves through this frame

## Rotation Representation Convention Comparison

### GT 272-Dim Format: ROW-MAJOR (via matrix_to_rotation_6d)
```python
# Line 116 in representation_272.py
final_x[:,8+6*njoint:8+12*njoint] = np.reshape(rotations_matrix[..., :, :2, :], (nfrm,-1))

# This takes first 2 rows of 3x3 matrix:
# [R00 R01 R02]
# [R10 R11 R12]  → 6D = [R00, R01, R02, R10, R11, R12]
# [R20 R21 R22]
```

### Alternative: quaternion_to_cont6d_np() — COLUMN-MAJOR (NOT used for GT)
From face_z_align_util.py lines 279-282:
```python
def quaternion_to_cont6d_np(quaternions):
    rotation_mat = quaternion_to_matrix_np(quaternions)
    cont_6d = np.concatenate([rotation_mat[..., 0], rotation_mat[..., 1]], axis=-1)
    return cont_6d
```

This takes first 2 COLUMNS:
```
# [R00 R01 R02]
# [R10 R11 R12]  → 6D = [R00, R10, R20, R01, R11, R21]
# [R20 R21 R22]     (col 0)        (col 1)
```

**GT 272-dim uses ROW-MAJOR, NOT this column-major version.**

## Data Processing Pipeline

### Stage 1: From AMASS/HumanML3D to SMPL Parameters
1. Original motion data (e.g., from AMASS) → SMPL parameters (axis-angle)
2. Stored as: `smpl_85_face_z_transform` files containing per-frame axis-angle rotations

### Stage 2: representation_272.py (Actual GT Generation)
```
Input:
  ├─ smpl_85_face_z_transform_joints (T, 22, 3) — joint positions from FK
  └─ smpl_85_face_z_transform (T, 85) — SMPL parameters

Processing:
  1. Extract SMPL axis-angles (first 66 dims of 85)
  2. Convert to quaternions [w,x,y,z]
  3. Convert to rotation matrices (3×3)
  4. Extract first 2 ROWS for 6D representation (ROW-MAJOR)
  5. Remove heading from all data
  6. Pack into 272-dim format

Output:
  └─ Representation_272/*.npy (T, 272)
```

### Stage 3: convert_prism_to_272.py (For PRISM Predictions)
```
Input:
  ├─ PRISM predictions (global_orient, body_pose, transl, betas)
  └─ Test annotation mapping

Processing:
  1. Apply face_z_transform to PRISM outputs
  2. Run SMPL FK to get joint positions
  3. Call compute_representation_272() with same logic as representation_272.py
  4. Uses matrix_to_rotation_6d() for 6D extraction (ROW-MAJOR)

Output:
  └─ prism_272_predictions/*.npy (T, 272) aligned to GT format
```

## Critical Implementation Details

### 1. SMPL Model Selection (NOT SMPLX!)
From convert_prism_to_272.py:
```python
body_model = smplx.create(
    model_path=args.smpl_model_dir,
    model_type='smpl',  # ← NOT 'smplx'
    gender='neutral',
    num_betas=10,
).to(args.device)
```

**Why**: SMPL has 22 joints, SMPLX has different body template. Using SMPLX produces "physically impossible skeletons."

### 2. Rotation Input from SMPL Direct Output
```python
# NOT applying any IK!
# The rotations come directly from:
rotation_smpl_axis_angle = rotation_smpl_axis_angle[:, :66]  # 22 joints × 3 axis-angle
```

These are AMASS/HumanML3D SMPL rotations, not inverse kinematics results.

### 3. First 2 ROWS Convention (ROW-MAJOR)
```python
# Line 116 in representation_272.py
rot6d = rotations_matrix[..., :2, :]  # (T, 22, 2, 3) shape
# Flattens to (T, 22*6)
```

This matches the Zhou et al. 2019 paper convention but **accessed row-wise**.

### 4. Heading-First Frame Reference
```python
# First frame always has identity heading (after face_z_transform)
final_x[0, 2] = 1   # index 2 = R[0,2] = 1 (identity matrix)
final_x[0, 6] = 1   # index 6 = R[1,1] = 1 (identity matrix)
```
