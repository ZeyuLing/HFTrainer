🔍 CODE STRUCTURE OVERVIEW
════════════════════════════════════════════════════════════════════════════

LAYER 1: TEXT ENCODER BUNDLE (encode_prompt_with_mask)
┌────────────────────────────────────────────────────────┐
│ Input: prompt string(s)                                │
│ Process:                                               │
│  1. Tokenize → [CLS, token1, token2, ..., PAD, PAD]   │
│  2. Encode via UMT5 → [1, max_len, hidden_dim]        │
│  3. Create mask → [1, 1, 1, 0, 0, ...]              │
│ Output: (embeddings, encoder_hidden_states_mask)      │
└────────────────────────────────────────────────────────┘

LAYER 2: TRAINING PATH (prism_trainer.py)
┌────────────────────────────────────────────────────────┐
│ train_step():                                          │
│  1. Call encode_prompt_with_mask()                    │
│  2. Get text_states & text_mask                        │
│  3. Pass to transformer:                              │
│     - encoder_hidden_states=text_states               │
│     - encoder_hidden_states_mask=text_mask            │
│ Result: Masked attention during training              │
└────────────────────────────────────────────────────────┘

LAYER 3: INFERENCE PATH (prism_backend.py)
┌────────────────────────────────────────────────────────┐
│ _get_t5_prompt_embeds_with_mask():                    │
│  1. Tokenize + encode prompts                         │
│  2. Create masks for each prompt                       │
│  3. Repeat embeddings by num_motion_per_prompt        │
│  4. Repeat masks by same factor                       │
│  Output: (embeddings, mask) with correct shapes       │
│                                                        │
│ encode_prompt_with_mask():                            │
│  1. Handle positive & negative prompts separately     │
│  2. Concatenate for CFG                              │
│  Output: (pos_emb, neg_emb, pos_mask, neg_mask)      │
│                                                        │
│ generate_single_segment():                            │
│  1. Get embeddings & masks from encode_prompt_with_mask
│  2. Pass masks to both CFG branches                  │
│  Output: Motion generation with masked text attention │
└────────────────────────────────────────────────────────┘

🎓 KEY LEARNINGS
════════════════════════════════════════════════════════════════════════════

1. Text Attention Masking
   - Padding tokens were diluting text signal significantly
   - Simple binary masks can improve attention efficiency 37x
   - Masking must be applied consistently across training/inference

2. CFG Implementation
   - Both positive and negative prompts need proper masking
   - Separate masks required for each branch
   - Repetition (num_motion_per_prompt) must apply to masks too

3. Architecture Consistency
   - Training and inference paths should use identical masking
   - Small inconsistencies can compound to quality issues
   - Unified encoding methods ensure consistency
