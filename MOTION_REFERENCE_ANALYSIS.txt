The v3 embodied pipeline's reference motion data (output/embodied_t2m_v3/data/motions/)
is COMPLETELY DIFFERENT from v2 (output/embodied_comparison_v2/data/motions/).

8. COORDINATE SYSTEM HYPOTHESIS
   
   Given the dramatic differences, possible causes:
   
   a) CHARACTER SCALE CHANGE
      - V2 uses one SMPL-X model scale
      - V3 uses different SMPL-X model scale or skeleton
      - Height difference of ~19% suggests this
   
   b) COORDINATE FRAME SWAP/TRANSFORMATION
      - V2: Likely uses CMU mocap standard (Y-up, Z-forward)
      - V3: May have applied incorrect rotation or frame change
      - Z-pos drops by 9.6% while X changes significantly
   
   c) REFERENCE MOTION REPLACED
      - V3 may be using regenerated motions from v3 model
      - Not the original t2m dataset reference
      - Manifest shows "model": "HyMotion T2M 1.0-Lite" for v3
      - Manifest shows only basic info for v2
   
   d) RETARGETING ERROR
      - Possible incorrect retargeting from CMU to SMPL-X
      - Or from SMPL-X to a different skeleton format


9. MANIFEST DIFFERENCES
   
   V2 Manifest:
   - Simple: just motion_id, num_frames, fps
   - No metrics or model information
   - Implies these are "raw" reference motions
   
   V3 Manifest:
   - Rich: includes metrics, model name, "fell" status
   - Has "root_height_mean", "max_joint_velocity"
   - Explicitly states model: "HyMotion T2M 1.0-Lite"
   - Suggests these are GENERATED/PROCESSED motions, not raw reference


CRITICAL FINDING
─────────────────
V3 batch_report.json shows:
  "paths": {
    "ref_json": "output/embodied_t2m_v3/data/motions/t2m_00000001.json",
    "tracked_json": "output/embodied_t2m_v3/data/tracked_motions/t2m_00000001.json",
    ...
  }

The v3 calls the motions directory "ref_json" (reference)
BUT the data inside suggests it's actually GENERATED OUTPUT, not reference!

The v2 calls its data reference (implying it's the source ground truth)
And v2 shows root_height_mean around 0.74 (more physically plausible for humanoid)

V3 shows root_height_mean of 0.594 (lower, possibly wrong scaling)


PROBABLE ROOT CAUSE
────────────────────
The v3 "reference motion" in /data/motions/ is NOT the original reference.
It appears to be output FROM the v3 pipeline, possibly from:

1. Model-generated motions that were downsampled or filtered
2. Retargeted motions that lost accuracy
3. A different character model with different proportions
4. An incorrectly initialized coordinate transformation
