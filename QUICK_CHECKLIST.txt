5. KEY DESIGN DECISIONS
================================================================================

[REQUIRED] Root DOF Handling:
  Question: Should RL policy control root position/rotation?
  Options:
    A) RL controls root → high-dimensional, needs careful reward design
    B) Environment provides root trajectory → simpler, motion-conditioned
    C) RL controls root rotation only, environment provides translation
  Recommendation: Option B for initial implementation (follow run_smpl_physics_sim.py)

[REQUIRED] Observation Representation:
  Question: What features in obs space?
  Options:
    A) Raw qpos/qvel (151 dims) — simple, but less semantic
    B) Computed features (FK output, joint angles) — richer, requires engineering
    C) Mixed: qpos/qvel + computed features
  Recommendation: Option C (start with A, add B iteratively)

[OPTIONAL] Reference Motion:
  Question: Should reward track motion clips from dataset?
  Options:
    A) Random reference initialization each episode
    B) Load motion from NPZ files (output/embodied_t2m_v4/data/npz/)
    C) Both: curriculum learning with increasing motion complexity
  Recommendation: Option B (motion-conditioned training)
