EULER ANGLE CONVERSION DETAILS
═══════════════════════════════════════════════════════════════════════════════

Default: euler_order="ZYX"

Scipy's as_euler("ZYX") = Intrinsic rotations in order Z → Y → X
   Applied as: R = Rz(θz) × Ry(θy) × Rx(θx)

This converts the rotation_matrix back to angle representation.
⚠️  No coordinate system conversion happens here - just rotation representation!

PELVIS OFFSET FROM XML (smpl_humanoid.xml, line 27)
═══════════════════════════════════════════════════════════════════════════════

<body name="Pelvis" pos="-0.0018 -0.2233 0.0282">

Breakdown of [-0.0018, -0.2233, 0.0282]:
  X: -0.0018  (slightly left)
  Y: -0.2233  (DOWN in Y-up, likely SMPL body offset)
  Z:  0.0282  (forward)

This offset is applied ADDITIVELY to the motion translation:
  final_pos = motion_trans + pelvis_offset

⚠️  If mj_model.body_pos[1] is interpreted in WORLD coordinates by MuJoCo,
    there could be a coordinate frame mismatch!


═══════════════════════════════════════════════════════════════════════════════
NORMALIZATION FUNCTION (normalize_smpl_pose)
═══════════════════════════════════════════════════════════════════════════════

When normalize=True is passed to smpl_to_qpose():

1. Extracts root euler angles using "xyz" order (line 610)
2. Modifies Z-rotation (line 617: target_root_euler[2] = -1.57 or random)
3. Recomputes rotation matrix and applies to pose_aa (line 626)
4. Adjusts translation height:
     trans[:, 2] = trans[:, 2] - trans[0, 2] + 0.91437225
   (Centers Z at 0, then sets to 0.91437225)

⚠️  This is a preprocessing step, not part of the main coordinate conversion!
