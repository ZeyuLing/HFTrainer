EULER ORDER: "ZYX" (HARDCODED DEFAULT)
- Z rotation first (yaw/heading)
- Y rotation second (pitch)  
- X rotation third (roll)

CRITICAL: The euler_order parameter exists in smpl_to_qpose() BUT qpos_to_smpl()

symmetry unless both are updated.

2. QPOS STRUCTURE & EULER ANGLE STORAGE
================================================================================

MuJoCo qpos format:
  [0:3]     Translation (x, y, z)
  [3:7]     Root Quaternion (stored as [x, y, z, w] in qpos)
  [7:10]    Body Joint 1 Euler Angles (ZYX order)
  [10:13]   Body Joint 2 Euler Angles (ZYX order)
  ...and so on for all body joints (3 DOF each)

ROOT JOINT (Index 0):
  - Stored as: Quaternion (4 components)
  - Format: [x, y, z, w] (MuJoCo format)
  - Internal scipy representation: [w, x, y, z]
  - Conversion overhead:
    * Encoding: as_quat()[:, [3, 0, 1, 2]] converts scipy→MuJoCo
    * Decoding: from_quat(quat[:, [1, 2, 3, 0]]) converts MuJoCo→scipy

BODY JOINTS (Index 1+):
  - Stored as: Euler Angles (3 components each)
  - Convention: ZYX (Z first, Y second, X third)
  - Extracted from qpos using body_qposaddr[bone_name]
  - Each joint gets exactly 3 consecutive qpos slots

================================================================================
3. COORDINATE TRANSFORMS: BODY JOINTS vs ROOT
================================================================================

ROOT JOINT SPECIAL HANDLING:
  1. Input: rotation matrix [4, 4] from angle_axis_to_rotation_matrix()
  2. Extract: [0, :3, :3] (the 3x3 rotation part)
  3. Convert: rotation_matrix_to_quaternion() → [w, x, y, z] (scipy)
  4. Reorder: [:, [3, 0, 1, 2]] → [x, y, z, w] (MuJoCo)
  5. Store: Slots [3:7] in qpos
  6. NOT reordered by smpl_2_mujoco

BODY JOINTS STANDARD HANDLING:
  1. Input: rotation matrices [num_joints, 3, 3]
  2. Convert: sRot.from_matrix() → Rotation objects
  3. Extract: as_euler("ZYX") → Euler angles [num_joints, 3]
  4. Reorder: Apply smpl_2_mujoco indices to reorder from SMPL→MuJoCo
  5. Store: In qpos slots starting from [7:]

KEY DIFFERENCE: Root uses quaternion (4 DOF), body joints use Euler angles (3 DOF)

CREATION:

      joint_names.index(q) for q in list(get_body_qposaddr(mj_model).keys())
      if q in joint_names

MEANING:

EXAMPLE:

  And MuJoCo order is [Pelvis, R_Hip, R_Knee, L_Hip, ...]
  Then smpl_2_mujoco = [0, 3, ?, 1, 2, ...]

USAGE (Line 391-393):
  1. Reshape SMPL poses: [batch, 24_joints, 3_angles]
  2. Index: [:, smpl_2_mujoco, :]
  3. Result: [batch, num_mujoco_joints, 3_angles]

  - Root quaternion is concatenated AFTER reordering:

6. COMPLETE FUNCTION FLOW
================================================================================

SMPL_TO_QPOSE FLOW:
  ┌─ SMPL axis-angle (24×3) + translation (1×3)
  ├─ angle_axis_to_rotation_matrix() → rotation matrices (24×3×3)
  ├─ sRot.from_matrix() → Rotation objects
  ├─ Root (index 0):
  │   └─ as_quat() → quaternion [w,x,y,z]
  │       → reorder to [x,y,z,w]
  │       → keep for later (no smpl_2_mujoco)
  ├─ Body joints (indices 1+):
  │   └─ as_euler("ZYX") → Euler angles
  │       → reshape to [batch, 24, 3]
  │       → reorder via smpl_2_mujoco
  │       → flatten back to [batch, num_body_joints×3]
  ├─ Concatenate: [translation, root_quat, body_eulers]
  ├─ Add body_pos[1] to translation (if count_offset=True)
  └─ Return: MuJoCo qpos

QPOS_TO_SMPL FLOW:
  ┌─ MuJoCo qpos (translation + quaternion + Euler angles)
  ├─ Extract translation: qpos[:, :3]
  ├─ Subtract body_pos[1] offset
  ├─ Root (index 0):
  │   └─ Extract quat from [3:7]
  │       → reorder from [x,y,z,w] to [w,x,y,z]
  │       → sRot.from_quat() → Rotation
  │       → as_rotvec() → axis-angle
  ├─ Body joints (indices 1+):
  │   └─ Extract Euler angles using body_qposaddr
  │       → sRot.from_euler("ZYX") → Rotation
  │       → as_rotvec() → axis-angle
  ├─ Assemble: [axis-angle for all 24 SMPL joints]
  └─ Return: (pose as axis-angle, translation)

7. IMPORTANT CAVEATS
================================================================================

1. ZYX INFLEXIBILITY
   - euler_order parameter in smpl_to_qpose() suggests flexibility
   - BUT qpos_to_smpl() has "ZYX" HARDCODED
   - Changing euler_order will BREAK round-trip conversion
   - Must update BOTH functions if changing convention

2. QUATERNION ORDERING MISMATCH
   - scipy uses [w, x, y, z]
   - MuJoCo expects [x, y, z, w]
   - Explicit reordering required at every conversion boundary
   - Error here = incorrect rotations

3. BODY JOINTS REORDERED, ROOT IS NOT
   - Root quaternion inserted BEFORE body joint reordering
   - Body joint Euler angles inserted AFTER reordering
   - This is intentional: root is in global frame, bodies are local

4. body_pos[1] OFFSET CRITICAL
   - When count_offset=True (default), translation includes pelvis offset
   - When count_offset=False, translation is relative to world origin
   - Asymmetric handling: smpl_to_qpose uses count_offset param,
     qpos_to_smpl ALWAYS subtracts (no parameter)

5. DEFAULT TRANSLATION HEIGHT
   - If trans=None: automatically set to z=0.91437225
   - This is a standing height, not ground height
   - Assumes pelvis at ~0.914 units above ground
