KEY INSIGHTS
═══════════════════════════════════════════════════════════════════════════════════════════════════

1. PADDING MASK PURPOSE
   ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
   │ • Created from num_frames: actual frame counts per batch element                            │
   │ • Marks frames beyond num_frames as invalid                                                │
   │ • Prevents loss computation on padded/dummy data                                           │
   │ • Applied identically to translation and rotation                                         │
   │ • Prevents attention from attending to padded frames (if transformer supports it)         │
   └─────────────────────────────────────────────────────────────────────────────────────────────┘

2. LOSS SEPARATION RATIONALE
   ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
   │ PROBLEM:                                                                                    │
   │   • Motion representation: 1 translation token + 22 rotation tokens = 23 total             │
   │   • Without separation: mse.mean() averages over all 23 tokens equally                     │
   │   • Translation weight: 1/23 ≈ 4.3% (diluted)                                              │
   │   • Rotation weight: 22/23 ≈ 95.7% (dominant)                                              │
   │   • Model may ignore translation signal                                                    │
   │                                                                                              │
   │ SOLUTION:                                                                                   │
   │   • Compute MSE separately for translation and rotation                                    │
   │   • Each gets its own normalized mean (weighted by valid/unconditioned frames)             │
   │   • Blend with configurable weights (default 0.5/0.5)                                     │
   │   • Allows fine-tuning relative importance                                                │
   └─────────────────────────────────────────────────────────────────────────────────────────────┘

3. MASKING INTERACTION
   ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
   │ full_mask combines TWO concepts:                                                            │
   │                                                                                              │
   │ ① PADDING MASK                                                                             │
   │    • 0 for frames beyond num_frames                                                       │
   │    • Prevents loss on "fake" padded data                                                   │
   │    • Batch element A: frames 0-31 valid, 32-44 padded                                     │
   │    • Batch element B: frames 0-44 valid, 45-52 padded                                     │
   │                                                                                              │
   │ ② CONDITION MASK                                                                           │
   │    • 0 for frames marked as "conditioned" (frozen)                                        │
   │    • Only ~10% of frames have condition_mask=0 (frame_condition_rate=0.1)                 │
   │    • These conditioned frames don't contribute to loss                                     │
   │    • Allows model to predict based on partial conditioning                                │
   │                                                                                              │
   │ COMBINED EFFECT:                                                                            │
   │    loss = 0 for frames that are EITHER padded OR conditioned                              │
   │                                                                                              │
   │    Example: B=2, T'=45                                                                     │
   │    ┌──────────────────────────────────────────────────────────────┐                      │
   │    │ Batch 0:  padding: [1,1,...,1(32×), 0,0,...,0(13×)]         │                      │
   │    │           condition: [1,0,1,...] (random ~90% ones)          │                      │
   │    │           full_mask: element-wise * product                  │                      │
   │    │                                                               │                      │
   │    │ Batch 1:  padding: [1,1,...,1(45×), 0,0,...,0(0×)]          │                      │
   │    │           condition: [1,0,1,...] (random ~90% ones)          │                      │
   │    │           full_mask: element-wise * product                  │                      │
   │    └──────────────────────────────────────────────────────────────┘                      │
   └─────────────────────────────────────────────────────────────────────────────────────────────┘

4. MOTION REPRESENTATION DETAIL
   ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
   │ Original SMPL: 55D = [tx, ty, tz, R_joint1(6D), R_joint2(6D), ..., R_joint22(6D)]         │
   │                                                                                              │
   │ In Latent Space (VAE encoded):                                                             │
   │ ┌──────────────────────────────────────────────────────────────────────────────────────┐  │
   │ │ Token 0: Translation (root global position) [B, 16, T', 1]                            │  │
   │ │          • 3D position (absolute + relative)                                        │  │
   │ │          • Encoded in 16 latent channels                                            │  │
   │ │                                                                                      │  │
   │ │ Tokens 1-22: Joint Rotations [B, 16, T', 22]                                        │  │
   │ │          • Token i = Rotation of SMPL joint i (22 joints total)                     │  │
   │ │          • 6D continuous rotation representation                                    │  │
   │ │          • Each encoded in 16 latent channels                                       │  │
   │ └──────────────────────────────────────────────────────────────────────────────────────┘  │
   │                                                                                              │
   │ Loss computation splits at the token dimension (last dimension):                          │
   │   • mse[:, :, :, :1]    → 1 token (translation)                                          │
   │   • mse[:, :, :, 1:]    → 22 tokens (rotation)                                           │
   └─────────────────────────────────────────────────────────────────────────────────────────────┘

5. CONFIGURATION IMPACT
   ┌─────────────────────────────────────────────────────────────────────────────────────────────┐
   │ From prism_1b_tp2m_1frame.py:                                                              │
   │                                                                                              │
   │ • condition_num_frames=[1]:           Only 1 frame used for conditioning                   │
   │ • frame_condition_rate=0.1:           ~10% of frames are conditioned                      │
   │ • max_text_length=256:                Max tokens for text embedding                        │
   │ • translation_loss_weight=0.5:        Equal weight for translation and rotation           │
   │                                                                                              │
   │ From prism_1b_tp2m_multiframe.py:                                                          │
   │ • condition_num_frames=[1,5,9]:       Random: 1, 5, or 9 frames for conditioning         │
   │   (This makes model more robust to variable conditioning)                                 │
   └─────────────────────────────────────────────────────────────────────────────────────────────┘
