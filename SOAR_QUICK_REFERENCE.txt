class HyMotionM2MSoarTrainer(HyMotionM2MTrainer):
    def __init__(
        self,

        soar_sigma_clamp: float = 0.05,    # Numerical stability lower bound

    )

MAIN METHOD: train_step(batch)
────────────────────────────────────────────────────────────────────────────────
Returns: Dict[str, Any] with keys:
  'loss'              → total_loss (scalar)
  'loss_velocity'     → base velocity loss
  'loss_motion_smoothness' → motion smoothness loss (if enabled)
  'loss_keypoints3d'  → FK loss (if enabled)
  'loss_soar_corr'    → SOAR correction loss

Flow:
  1. ctx = _prepare_and_forward(batch)  # Base forward (inherited)
  2. base_losses = _compute_base_loss(ctx)
  3. corr_loss = _soar_correction_loss(ctx)
  4. total_loss = sum(base_losses) + soar_lambda * corr_loss
  5. return {'loss': total_loss, ...}

═══════════════════════════════════════════════════════════════════════════════

CORE METHOD: _soar_correction_loss(ctx)
────────────────────────────────────────────────────────────────────────────────
Location: lines 143-251

STEP R1: Stop-Gradient Rollout
  t1 = clamp(t0 + 1/K, max=1.0)
  x_hat = detach(x_t0 + detach(v_pred) * (t1 - t0))
  Apply mask-aware: x_hat[known] = x_clean

STEP R2: N Auxiliary Re-Noise + Correction (for each n in range(N)):
  
  Auxiliary Timestep:
    t' ~ U[0, t1]
    alpha = 1 - (t' / t1)
    z_re = alpha * x_hat + (1 - alpha) * x0
    Apply mask-aware: z_re[known] = x_clean
  
  Correction Target:
    sigma_t' = clamp(1 - t', min=sigma_clamp)
    v_corr = (x1 - z_re) / sigma_t'
  
  Forward Pass (WITH GRADIENT):
    v_off = model(cat([z_re, vace_ctx], dim=-1), cond, t')
  
  Loss:
    corr = smooth_l1_loss(v_off, detach(v_corr), generation_mask=src_mask)

Return: mean(all auxiliary losses) over N points

DATA FLOW
────────────────────────────────────────────────────────────────────────────────
Input Batch (from M2M DataLoader):
  src_motion      (B, L, D)  → Source motion for VACE context
  tgt_motion      (B, L, D)  → Target motion to generate
  src_mask        (B, L, D)  → Binary: 0=known, 1=generate
  src_length      List[int]  → Actual frame counts
  tgt_length      List[int]  → Actual frame counts
  [optional: caption, text embeddings, ref_pose]

After Preparation (_prepare_and_forward):
  x0              (B, L, D)  → Gaussian noise
  x1              (B, L, D)  → Normalized tgt_motion
  x_t             (B, L, D)  → (1-t)*x0 + t*x1 (on-trajectory)
  v_pred          (B, L, D)  → Model prediction at x_t
  vace_context    (B, L, 3D) → VACE conditioning

SOAR Internal States:
  x_hat           (B, L, D)  → Off-trajectory (detached)
  z_re            (B, L, D)  → Re-noised auxiliary (detached)
  v_off           (B, L, D)  → Model on z_re (REQUIRES GRAD)
  v_corr          (B, L, D)  → Correction target (detached)

═══════════════════════════════════════════════════════════════════════════════

MASK-AWARE NOISE HANDLING
────────────────────────────────────────────────────────────────────────────────
4 Application Points:
  1. Initial x_t        → x_t[known] = x1 (standard _man)
  2. After rollout x_hat → x_hat[known] = x1
  3. Re-noised z_re     → z_re[known] = x1
  4. Loss computation   → Only weight generation regions

Key Concept:
  - src_mask: (B, L, D) binary, 1=generate, 0=known
  - keep_mask = 1 - src_mask
  - x_masked = x * src_mask + x1 * keep_mask

═══════════════════════════════════════════════════════════════════════════════

GRADIENT FLOW
────────────────────────────────────────────────────────────────────────────────
Base Forward:                  x_t0 → model → v_pred
                               └── backward ← L_base

Rollout (STOP GRADIENT):       v_pred.detach() → [no gradients]

Correction Forward:            z_re.detach() → model → v_off
                               └── backward ← L_corr

Critical Boundaries:
  - v_pred used in rollout is DETACHED (stop-gradient)
  - x_hat is DETACHED (no gradient through rollout)
  - z_re is DETACHED (no gradient through re-noising)
  - v_off carries gradients (backprop through correction model)
  - v_corr target is DETACHED (fixed, not optimized)

═══════════════════════════════════════════════════════════════════════════════

COMPUTATIONAL COST
────────────────────────────────────────────────────────────────────────────────
Forwards per step (N=1 case):
  1. Base forward        (with grad)    → v_pred
  2. Rollout forward     (no grad)      → v_rollout (same as v_pred)
  3. Correction forward  (with grad)    → v_off
  
  Total: ~3 logical forwards, 2 backward passes

Multiplier vs SFT: ~2.0x per-step cost (no-grad rollout is cheap)

Memory Impact:
  - Base SFT:        ~20 GB (8xA100, BS=28)
  - SOAR (N=1):      ~35-40 GB (8xA100, BS=14) → 1.75-2.0x
  
Training Time (8xA100):
  - SOAR E1 (5K steps):  ~3.5 hours
  - SOAR E4 (10K steps): ~7 hours
  - Full ablation:       ~21 hours

LOSS COMPONENTS
────────────────────────────────────────────────────────────────────────────────
L_total = L_base + lambda_soar * L_corr

L_base:
  - Component losses from parent trainer's m2m_loss
  - Typically: L_velocity + L_motion_smoothness + [L_FK + L_keypoints3d]
  - Loss type: SmoothL1 (smooth Huber loss)

L_corr:
  - Mean of N auxiliary smooth_l1_loss(v_off, v_corr)
  - Masked by generation_mask: only generated regions
  - Averaged before final weighting

Combined Loss:
  - Simple additive combination
  - Both components use same loss function (SmoothL1)
  - No custom normalization factor (inherited from parent)

MONITORING METRICS
────────────────────────────────────────────────────────────────────────────────
TensorBoard Keys:
  loss                     → Total loss (should trend downward)
  loss_velocity            → Base velocity loss (should stay stable)
  loss_soar_corr           → Correction loss (should trend downward)
  loss_motion_smoothness   → Motion smoothness (if enabled)
  
Healthy Training Indicators:
  ✓ loss_velocity: 0.3-0.5 range, stable
  ✓ loss_soar_corr: > 0, decreasing trend
  ✓ Total loss: decreasing trend
  ✓ Ratio loss_soar_corr/loss_velocity ≈ lambda (≈0.1)
  ✓ No NaN/Inf values
  ✓ GPU memory stable ~35-40GB

Warning Signs:
  ✗ loss_velocity increases → lambda too high
  ✗ loss_soar_corr stays flat → correction not working
  ✗ NaN in loss → sigma_clamp too small
  ✗ OOM → batch size or gradient checkpointing issue

KEY DIFFERENCES vs BASE TRAINER
────────────────────────────────────────────────────────────────────────────────
Base M2M SFT Trainer:
  - Single forward pass per step
  - On-trajectory states only
  - Dense base loss supervision
  - No explicit exposure bias correction

SOAR Post-Trainer:
  - Dual forward passes (base + correction)
  - One-step rollout → off-trajectory state
  - N auxiliary re-noise points per sample
  - Dense correction supervision on off-trajectory states
  - ~2x per-step cost, ~1.75-2x memory, short duration (5-10K steps)

Complementary to _man (mask-aware noise):
  - _man fixes known regions (clean ↔ clean)
  - SOAR fixes generated regions (off-trajectory ↔ on-ray)
  - Together: orthogonal coverage of both train/test mismatch sources
