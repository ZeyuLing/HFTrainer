================================================================================
ROOT CAUSE IDENTIFIED
================================================================================

The deformation is NOT due to configuration mismatches. Instead, it stems from
FLOATING-POINT PRECISION ISSUES in the sigma lookup process.

PRIMARY CULPRIT: _get_sigmas() function in bundle.py (lines 19-27)

Current code uses EXACT EQUALITY matching:
  step_indices = [(schedule_timesteps == t).nonzero().item() for t in timesteps]

PROBLEM:
- Timestep values like 999.8005981445312 fail to exactly match 999.8
- Floating-point rounding errors accumulate during per-token expansion
- If a timestep doesn't match, .nonzero() raises IndexError
- This causes training to crash or inference to produce garbage sigmas

SECONDARY ISSUES:
1. Timestep distribution mismatch: Training sees all 1000 values uniformly,
   inference only sees 10 specific values in sequence
2. Per-token expansion logic: Different mask generation between training/inference
3. Type mismatches: float32 vs bf16 conversions during latent processing

================================================================================
QUICK FIX (HIGH CONFIDENCE)
================================================================================

Replace exact equality with nearest-neighbor lookup in _get_sigmas():

  OLD (FRAGILE):
    step_indices = [(schedule_timesteps == t).nonzero().item() for t in timesteps]
  
  NEW (ROBUST):
    step_indices = []
    for t in timesteps:
        distances = (schedule_timesteps - t).abs()
        closest_idx = distances.argmin().item()
        step_indices.append(closest_idx)

This single change should resolve most motion deformation issues.

File to edit: hftrainer/models/motion/prism/bundle.py
Function: _get_sigmas() [lines 19-27]

TECHNICAL DETAILS

Training Timestep Sampling:
  step_indices = torch.randint(0, len(scheduler.timesteps), (batch_size,))
  timesteps = scheduler.timesteps[step_indices]
  Result: Random uniform sampling from all 1000 timesteps

Inference Timestep Scheduling:
  scheduler.set_timesteps(num_inference_steps=10, device=device)
  timesteps = scheduler.timesteps
  Result: Fixed sequence [1000, 975.7, 946.3, ..., 24.4]

Per-Token Timestep Expansion:
  Training: target_ts expanded across all joints, then zeroed for condition frames
  Inference: first_frame_mask used to zero condition frames
  Both should produce same shapes if patch_size=(1,1)

Sigma Lookup Vulnerability:
  Current: Exact equality requires timestep values to match precisely
  Problem: Float precision causes mismatches on values like 999.8005981445312
  Solution: Nearest-neighbor approach tolerates small rounding errors

CONCLUSION

floating-point precision handling in the sigma lookup function. The fix is

resolve the majority of deformation issues while being backward-compatible
with existing code.
